# office-worker 引き継ぎ

## 目的と実装済みの範囲

事業1の受託・再利用用部品です。YAMLレシピでCSV/Excel/PDFの読み込み、整形、集計、保存、Sheets連携、通知、退避を組み合わせます。CLI、FastAPI、n8nフローの雛形、GAS雛形、案件フォルダ作成、AI実装支援、exe化の入口まであります。

[3リポジトリ全体の構成・合併判断](BUSINESS_ARCHITECTURE.md)を参照してください。動画リポジトリは対象外です。

## 今回の修正

- CSV/PDFをファイルごとに処理し、失敗は `error.log` と失敗一覧に残して続行。全件失敗は明示エラー。
- レシピの `move` は読み取りに失敗したファイルを退避しない。
- APIアップロードはリクエストごと・ファイルごとに分離。同名の添付でも上書きしない。
- APIの出力先を `OW_ROOT` 内に制限。Excel書き込みはロック。
- 全角の請求額を正規化し、抽出額の切り詰めを修正。
- 空白PDFはOCR未対応として入力に残し、金額0は欠損と区別して保持。
- OpenHandsの導入は `setup.ps1 -WithAgent` / `setup.sh --with-agent` を指定した時だけ。
- 回帰テストとGitHub Actionsのテスト実行を追加。

## 再レビューで追加した保護

- `move` は読み込みに成功した入力だけを対象にします。処理中に到着した別ファイルや、読み込んでいないファイルは入力に残します。
- 退避先に同名ファイルがある場合は `invoice-2.csv` のような別名で保存し、既存の原本を上書きしません。コピー完了前に失敗した場合は入力を削除しません。
- 入力0件は明示エラーにし、既存の出力を空の結果で上書きしません。
- 請求合計金額を抽出できないPDFは失敗一覧に残し、自動退避しません。金額0は有効な値として保持し、小数額を途中で切り捨てません。
- CSVの数値変換は全角数字・全角カンマ・全角マイナスを正規化してから行います。
- APIの出力名には依頼ごとの識別子を付け、同日・同名の次の処理で過去の結果を上書きしません。実際の保存先はレスポンスの `file` を使ってください。

## 再開コマンド

リポジトリ直下でPython 3.12以上を使います。

```powershell
.\setup.ps1
.\.venv\Scripts\python -m officeworker run recipes\merge_sales.yaml
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m unittest discover -s tests -v
```

売上サンプルの期待結果は明細5行、店舗別3行。池袋=2900、渋谷=2700、新宿=800です。出力Excelには「明細」「店舗別」の2シートができます。既定環境で実行して、この集計を確認しました。

Python 3.12の専用venvに基本依存とテスト依存を新規導入し、回帰テスト、売上サンプル、`pip check` を確認しました。初回13件に加え、再レビューで未処理ファイルの退避・原本上書き・空入力・金額欠損などの回帰テストを追加しています。

Linuxでは `bash setup.sh` の後に `.venv/bin/python` で同じコマンドを実行できます。

## 失敗の確認

CLIでは実行ログと `error.log`、Pythonからは `df.attrs["failed_files"]`、レシピからは `ctx["failed_files"]` を確認します。APIは `failed_files` を返し、全件読み取り失敗はHTTP 422、入力なしは400です。部分成功を完全成功と扱わず、入力に残った失敗ファイルを修正して再処理してください。

### 見直しで直した不具合
- `merge_sales.yaml` の `dedupe: [date, store, item]` は **同じ日・店・商品の正当な2件目の売上を消して過少計上**していた。行の重複削除をやめ、二重投入は「中身が同一のファイル」で除外（`load: {skip_duplicate_files: true}`）
- `to_number` が空欄セルで例外（pandas 3 では `astype(str)` が NaN を残す）→ 空欄は NaN として扱う。`▲300` `△300` `(300)` はマイナスに
- `to_date` が `2026年10月1日`・和暦・`20261001` を空にしていた → 解析を追加
- 店ごとに列名が違うと統合後に列が重複して壊れた → `load` の `rename` / `normalize_columns` / `require` / `labels` でファイル単位にそろえ、必須列の無いファイルは失敗一覧へ（入力に残す）
- 追加ステップ: `quarantine`（必須項目が空の行を要確認へ）、`pivot`、`keep`/`use`（分岐集計）、`groupby` の名前付き集計、`save: {new: true}`。Excel の数値は桁区切り表示

## 2026-10-31 見直し（2回目）
- 日付は「先頭が4桁の年」の形式だけ解釈。`26/10/01`（以前は 2001-10-26 に化けた）・`10/1`（今年扱いになった）は推測せず要確認へ
- `−`（数学のマイナス U+2212）等もマイナスとして扱う
- 二重投入の判定に「行の中身が同じ」も追加（Excel で開いて保存し直したコピーも検出）。`~$` で始まる Excel のロックファイルは無視
- 商品は全列を文字で読み込み、コードの先頭ゼロを保持。集計Excelを開いたままの再実行・空の in フォルダは日本語で案内
- `sheets.push`: 先に clear しない（通信失敗でシートが空にならない）、1000行超で拡張、日付を送れる、`=`/`@` 始まりの文字を式として実行させない
- `watch`: ファイルの大きさ・更新時刻が落ち着いてから実行（コピー途中のファイルを読まない）
- API は既定で `127.0.0.1` のみ受付。`--host 0.0.0.0` は `OW_API_TOKEN` 必須。n8n フローは `x-token` を送る（`.env` の値をコンテナへ渡す）。Docker Desktop で n8n から 127.0.0.1 の API に届くかは未確認、届かない場合は README の手順で公開
